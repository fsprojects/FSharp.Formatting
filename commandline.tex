\section*{Command line}



To use F\# Formatting tools via the command line, you can use the \texttt{fsdocs} dotnet tool.
\begin{lstlisting}
dotnet tool install fsdocs-tool
dotnet fsdocs [command] [options]

\end{lstlisting}
\subsection*{The build command}



This command processes a \texttt{docs} directory and generates API docs for projects in the solution according to the
rules of \href{apidocs.html}{API doc generation}. The input accepted is described in \href{content.html}{content}.
\begin{lstlisting}
fsdocs build

\end{lstlisting}


The command line options accepted are:
\begin{tabular}{|l|l|}\hline
\textbf{Command Line Option} & \textbf{Description}\\ \hline\hline
\texttt{--input} & Input directory of content (default: \texttt{docs})\\ \hline
\texttt{--projects} & Project files to build API docs for outputs, defaults to all packable projects\\ \hline
\texttt{--output} & Output Directory (default 'output'). Ignored by \texttt{watch}, which keeps no output folder.\\ \hline
\texttt{--ignoreuncategorized} & Disable generation of the 'Other' category in the navigation bar for uncategorized docs\\ \hline
\texttt{--noapidocs} & Disable generation of API docs\\ \hline
\texttt{--ignoreprojects} & Disable project cracking\\ \hline
\texttt{--eval} & Evaluate F\# fragments in scripts\\ \hline
\texttt{--saveimages} & Save images referenced in docs (\texttt{none}{\textbackslash}|\texttt{some}{\textbackslash}|\texttt{all}, default: \texttt{none}). If \texttt{some}, images are downloaded and saved locally for LaTeX (\texttt{.tex}) and notebook (\texttt{.ipynb}) outputs. If \texttt{all}, images are also saved for HTML and Markdown outputs. See \href{\#embedding-images}{Embedding Images} for details.\\ \hline
\texttt{--nolinenumbers} & Don't add line numbers, the default is to add line numbers.\\ \hline
\texttt{--parameters} & Additional substitution parameters for templates\\ \hline
\texttt{--nonpublic} & The tool will also generate documentation for non-public members\\ \hline
\texttt{--nodefaultcontent} & Do not copy default content styles, javascript or use default templates\\ \hline
\texttt{--clean} & Clean the output directory. Ignored by \texttt{watch}, which keeps no output folder.\\ \hline
\texttt{-v}, \texttt{--verbosity} & How much to log: \texttt{quiet} (errors only), \texttt{minimal} (and warnings), \texttt{normal} (default: one line per phase, and in \texttt{watch} one line per change and per page built), \texttt{detailed} (one line per file, the substitutions, the cracked projects) or \texttt{diagnostic} (everything, with timestamps). Warnings and errors go to standard error, the rest to standard output.\\ \hline
\texttt{--help} & Display this help screen\\ \hline
\texttt{--version} & Display version information\\ \hline
\texttt{--properties} & Provide properties to dotnet msbuild, e.g. --properties Configuration=Release Version=3.4\\ \hline
\texttt{--fscoptions} & Additional arguments passed down as \texttt{otherflags} to the F\# compiler when the API is being generated.<br/>Note that these arguments are trimmed, this is to overcome \href{https://github.com/commandlineparser/commandline/issues/58}{a limitation in the command line argument processing}.<br/>A typical use-case would be to pass an addition assembly reference.<br/>Example \texttt{--fscoptions " -r:MyAssembly.dll"}\\ \hline
\texttt{--strict} & Fail if docs are missing or can't be generated\\ \hline
\end{tabular}



The following command line options are also accepted but it is instead recommended you use
settings in your .fsproj project files:
\begin{tabular}{|l|l|}\hline
\textbf{Command Line Option} & \textbf{Description}\\ \hline\hline
\texttt{--sourcefolder} & Source folder at time of component build (\texttt{<FsDocsSourceFolder>})\\ \hline
\texttt{--sourcerepo} & Source repository for github links (\texttt{<FsDocsSourceRepository>})\\ \hline
\texttt{--mdcomments} & Assume comments in F\# code are markdown (\texttt{<UsesMarkdownComments>})\\ \hline
\end{tabular}

\subsection*{Project file settings}



Many fsdocs behaviours can be controlled via MSBuild properties in your \texttt{.fsproj} (or \texttt{Directory.Build.props}) file.
\begin{tabular}{|l|l|l|}\hline
\textbf{Property} & \textbf{Default} & \textbf{Description}\\ \hline\hline
\texttt{<GenerateDocumentationFile>true</GenerateDocumentationFile>} & \texttt{false} & Required — enables XML doc generation so fsdocs can produce API docs for this project.\\ \hline
\texttt{<FsDocsAllowExecutableProject>true</FsDocsAllowExecutableProject>} & \texttt{false} & Include this project even though its \texttt{OutputType} is not \texttt{Library}.\\ \hline
\texttt{<UsesMarkdownComments>true</UsesMarkdownComments>} & \texttt{false} & Treat \texttt{///} doc comments as Markdown rather than XML doc. Equivalent to \texttt{--mdcomments}.\\ \hline
\texttt{<FsDocsWarnOnMissingDocs>true</FsDocsWarnOnMissingDocs>} & \texttt{false} & Emit warnings for public members that have no documentation comments.\\ \hline
\texttt{<FsDocsSourceFolder>src</FsDocsSourceFolder>} & \emph{(auto)} & Root source folder used when constructing source-link URLs. Equivalent to \texttt{--sourcefolder}.\\ \hline
\texttt{<FsDocsSourceRepository>https://github.com/…/blob/main</FsDocsSourceRepository>} & \emph{(auto from repo)} & Repository URL prefix for source links. Equivalent to \texttt{--sourcerepo}.\\ \hline
\texttt{<FsDocsCollectionNameLink>https://example.com</FsDocsCollectionNameLink>} & \emph{(none)} & URL for the collection-name link in the navigation header.\\ \hline
\texttt{<FsDocsLogoSource>img/logo.png</FsDocsLogoSource>} & \emph{(none)} & Path to the logo image shown in the header.\\ \hline
\texttt{<FsDocsLogoAlt>My Project</FsDocsLogoAlt>} & \texttt{Logo} & Alt text for the header logo (accessibility).\\ \hline
\texttt{<FsDocsLogoLink>https://example.com</FsDocsLogoLink>} & \emph{(none)} & URL the logo links to.\\ \hline
\texttt{<FsDocsFaviconSource>img/favicon.ico</FsDocsFaviconSource>} & \emph{(none)} & Path to the favicon.\\ \hline
\texttt{<FsDocsTheme>default</FsDocsTheme>} & \texttt{default} & Theme to use for generated HTML.\\ \hline
\texttt{<FsDocsLicenseLink>https://…/LICENSE</FsDocsLicenseLink>} & \emph{(none)} & URL to the project licence, shown in the footer.\\ \hline
\texttt{<FsDocsReleaseNotesLink>https://…/RELEASE\_NOTES.md</FsDocsReleaseNotesLink>} & \emph{(none)} & URL to the release notes, shown in the footer.\\ \hline
\texttt{<FsDocsNoInheritedMembers>true</FsDocsNoInheritedMembers>} & \texttt{false} & Suppress the "Inherited from X" sections on type pages.\\ \hline
\texttt{<FsDocsTypeConstraints>Short</FsDocsTypeConstraints>} & \texttt{Short} & Controls how generic type constraints are displayed in member tooltips. \texttt{None} hides constraints entirely; \texttt{Short} (default) shows them inline using the compact \texttt{(requires ...)} style (e.g. \texttt{'T (requires equality)}); \texttt{Full} shows them in a separate "Constraints:" section with full \texttt{when} syntax.\\ \hline
\texttt{<FsDocsGenerateLlmsTxt>false</FsDocsGenerateLlmsTxt>} & \texttt{true} & Generate \texttt{llms.txt} and \texttt{llms-full.txt} for LLM consumption alongside the HTML output.\\ \hline
\end{tabular}



The command will report on any \texttt{.fsproj} files that it finds, telling you if it decides to skip a particular file and why.


For example, a project will be skipped if:
\begin{itemize}
\item 

The project name contains ".Tests" or "test" (because it looks like a test project)

\item 

The project does not contain
\begin{lstlisting}[numbers=left]

[escapeinside=\\\{\}]
{<}\id{GenerateDocumentationFile}{>}\kwd{true}\ops{</}\id{GenerateDocumentationFile}{>}


\end{lstlisting}


\item 

The project \texttt{OutputType} is not \texttt{Library}. To include an executable project, add this to the project file:
\begin{lstlisting}[numbers=left]

[escapeinside=\\\{\}]
{<}\id{FsDocsAllowExecutableProject}{>}\kwd{true}\ops{</}\id{FsDocsAllowExecutableProject}{>}


\end{lstlisting}


\end{itemize}

\subsection*{The watch command}



This command serves the documentation from memory while you edit it. Nothing is written to disk: a page is
built the first time the browser asks for it and kept until a file that influences it changes. Static files
such as images and css are served from their source location. A browser will be launched automatically
(unless \texttt{--nolaunch} is specified).
\begin{lstlisting}
fsdocs watch

\end{lstlisting}


The input directory (e.g. \texttt{docs}) and the extra content shipped with the tool are watched, together with the
project files, the solution-wide MSBuild files (\texttt{Directory.Build.props} and friends) and the project output
DLLs used for the API docs. Every change goes through the same pipeline: the file is
stat-ed, its content hashed when the content matters, and only a real change invalidates the pages that
depend on it. A byte-identical rewrite (for example by a formatter) invalidates nothing. Editing a heading in
\texttt{a.md} rebuilds \texttt{a.html} on the next request and refreshes the navigation of the other pages without
rebuilding them; a project DLL or project file change re-cracks the projects and rebuilds the API reference in the
background. The API reference is also built in the background at startup, so the first page does not wait
for it. A background reconciler walks the watched folders every two seconds as a guard against missed file system events.


A page that fails to build returns a \texttt{500} with the error message; the other pages keep working and the
process stays up, even with \texttt{--strict}.


The search index (\texttt{index.json}) and \texttt{llms.txt} are the only URLs that need every page, and they are only
requested when the search dialog is first opened.


Two diagnostic pages are served under the reserved \texttt{/.fsdocs/} prefix:
\begin{itemize}
\item \texttt{/.fsdocs/doctor}: the projects that were cracked, whether their design-time build ran and which
substitutions it changed (properties set by MSBuild targets, such as a version computed from a
changelog, are only known after it; a button runs it again), the substitutions and where they come
from, the templates that were tried and chosen, the navigation with the source of every title, the
routes, the state of every requested page, the recent file events, the collected errors and the
recent log lines.

\item \texttt{/.fsdocs/doctor.json}: the same as JSON, handy for troubleshooting with an LLM.

\end{itemize}



Adding a project to the solution, or changing a project's output path, still needs a restart. The same
parameters as \texttt{build} are accepted
(\texttt{--output}, \texttt{--clean} and \texttt{--saveimages} are ignored with a note), plus these:
\begin{tabular}{|l|l|}\hline
\textbf{Command Line Option} & \textbf{Description}\\ \hline\hline
\texttt{--nolaunch} & Do not launch a browser window.\\ \hline
\texttt{--open} & URL extension to launch \href{http://localhost:<port>/\%s.}{http://localhost:<port>/\%s.}\\ \hline
\texttt{--port} & Port to serve content for \href{http://localhost}{http://localhost} serving.\\ \hline
\texttt{--host} & Address to bind the server to (default \texttt{localhost}). Use \texttt{0.0.0.0} to browse from another machine on the network; page links are relative, so the site works from any address.\\ \hline
\texttt{--site-root} & The absolute URL of the site (\texttt{\{\{fsdocs-site-root\}\}}), only used by the links that must be absolute such as Open Graph metadata and \texttt{llms.txt}. Defaults to \texttt{http://<host>:<port>/}.\\ \hline
\end{tabular}

\subsection*{Searchable docs}



When using the command-line tool a \href{https://www.fusejs.io/}{Fuse} search index is automatically generated in \texttt{index.json}.
A search box is included in the default template via an \href{https://developer.mozilla.org/docs/Web/HTML/Element/dialog}{HTML Dialog element}.

To add search to your own \texttt{\_template.html}:
\begin{itemize}
\item include an HTML element with id \texttt{search-btn}

\item include a \texttt{dialog} element

\item include \texttt{fsdocs-search.js} script

\end{itemize}

\begin{lstlisting}
<button id="search-btn">Open search dialog</button>
<dialog>
    <input type="search" placeholder="Search docs" />
    <div class="results">
        <ul></ul>
        <p class="empty">Type something to start searching.</p>
    </div>
</dialog>
<script type="module" src="{`{root}}content/fsdocs-search.js"></script>

\end{lstlisting}
\subsection*{Embedding Images}

\subsubsection*{Downloading Remote Images (\texttt{--saveimages})}



The \texttt{--saveimages} flag controls whether images referenced in your docs are downloaded and saved locally alongside the generated output. This is primarily useful for non-HTML output formats such as LaTeX (PDF) and Jupyter Notebook (\texttt{.ipynb}), which cannot reference remote URLs at display time.
\begin{tabular}{|l|l|}\hline
\textbf{Value} & \textbf{Behaviour}\\ \hline\hline
\texttt{none} (default) & Images are referenced by their original URL; nothing is downloaded.\\ \hline
\texttt{some} & Images are downloaded and saved for LaTeX and notebook outputs only.\\ \hline
\texttt{all} & Images are downloaded and saved for all output formats including HTML and Markdown.\\ \hline
\end{tabular}



Example:
\begin{lstlisting}
fsdocs build --saveimages some

\end{lstlisting}
\subsubsection*{Embedding Images Generated by Scripts}



When using \texttt{--eval} to evaluate literate F\# scripts, you can embed images produced by code (e.g. charts, plots) directly into the HTML output.


\textbf{Option 1: Inline Base64 image using \texttt{include-it-raw}}


Write a helper that reads an image file and returns an HTML \texttt{<img>} tag with the image data embedded as a Base64 string. Then use \texttt{(*** include-it-raw ***)} to inject the raw HTML into the output:
\begin{lstlisting}[numbers=left]

[escapeinside=\\\{\}]
\kwd{let} \id{inlinePng} {(}\id{fileName}{:} \id{string}{)} \ops{=}
    \kwd{let} \id{bytes} \ops{=} \id{System}{.}\id{IO}{.}\id{File}{.}\id{ReadAllBytes}{(}\id{fileName}{)}
    \kwd{let} \id{b64} \ops{=} \id{System}{.}\id{Convert}{.}\id{ToBase64String}{(}\id{bytes}{)}
    \id{sprintf} \str{"""<img src="data:image/png;base64,\%s" />"""} \id{b64}

\com{// Generate the image in your script, then embed it:}
\com{// myChart.SavePng("chart.png")}
\com{// (*** hide ***)}
\com{// inlinePng "chart.png"}
\com{// (*** include-it-raw ***)}


\end{lstlisting}



The \texttt{(*** hide ***)} command suppresses the source code of the expression, so only the rendered image appears in the output.


\textbf{Option 2: Custom HTML printer via \texttt{fsi.AddHtmlPrinter}}


If your charting library produces values of a known type, you can register a custom HTML printer so that values of that type are automatically rendered as images whenever they appear via \texttt{(*** include-it ***)}. See \href{evaluation.html\#using-addprinter-and-addhtmlprinter}{Embedding Script Output} for details.
